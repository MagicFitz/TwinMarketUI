# Getting Started

这篇文档说明 TwinMarket 的市场仿真在做什么，模型要怎样配置，以及怎样在 Research Studio 里创建并启动第一个实验。

## 市场仿真在讲什么

TwinMarket 用大语言模型驱动一批投资者 Agent，在一个按自然日推进的股票市场里读信息、发帖和交易。TwinMarketUI 把同一次模拟收成一次可配置、可停止、可回看的实验。

一次实验固定三件事：哪些 Agent 参加、使用哪一段行情和新闻、模型按什么参数做决策。创建时，这些输入写入该实验自己的目录 `backend/runs/<run_id>/`，其中包括 `manifest.json` 和 `state.json`。之后再改全局模型设置或市场数据，不会改写已经创建的实验。

工作台「运行进度」里，一个交易日按这个顺序推进：

| 阶段 | 发生的事 |
| --- | --- |
| 环境准备 | 准备当日行情、新闻，以及 Agent 能看到的上下文 |
| Agent 决策 | 当天被激活的 Agent 调用语言模型，形成看法，并提交订单或帖子 |
| 市场撮合 | 按实验选定的市场规则撮合订单 |
| 社交互动 | 把帖子写入论坛式社交网络，供之后的交易日阅读 |
| 提交当日 | 记下检查点。这一天成功提交后，失败或停止可以从下一日续跑 |

不是每个 Agent 每天都会行动。创建实验时的「激活概率」决定当天大约有多大比例的 Agent 会调用模型。休市日可以有论坛活动，但没有成交。

Agent 来自本地投资者模板，默认群体有 1000 人，可以在「智能体」里查看地域、投资者类型和持仓等分布。单个人的决策按信念、愿望、意图展开：先解释看到的信息，再决定想做什么，最后形成订单或发言。实验工作台里打开某个 Agent，可以按日回看这些内容。画像和偏差是输入，不是行为金融测验的结论。

市场输入有两种：

- **市场模板**是新建实验的默认选项。市场数据服务按模板检查日期覆盖，并冻结一份行情、日历和新闻。实验之后一直使用这份冻结数据。
- **内置历史文件**直接使用仓库自带的行情和新闻，不经过模板。适合只用随仓库提供的数据做一次短实验。

模拟关心的不是某一次预测对不对，而是很多 Agent 的订单和发言放在一起之后，价格和讨论是否出现厚尾、波动聚集这类市场典型事实。区间只有一两个交易日时，分析页会说明样本不足，而不是画出没有依据的图。

## 基础配置

在仓库中准备环境并启动工作台：

```bash
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r server/requirements.txt
cp config/api_example.yaml config/api.yaml
cp config/embedding_example.yaml config/embedding.yaml
scripts/dev.sh
```

浏览器打开 <http://127.0.0.1:5173/studio/>。`dev.sh` 会同时启动市场数据服务（8100）、仿真后端（8766）和前端（5173）。示例配置里的地址和密钥只是占位，不能拿来跑实验。端口可以用 `MDS_PORT`、`BACKEND_PORT` 和 `FRONTEND_PORT` 修改。

### 语言模型

打开 **设置**。语言模型是 Agent 决策和发帖使用的 Chat Completions 接口。填写 OpenAI 兼容服务的 Base URL、模型名称，以及该服务要求的 API Key。不校验密钥的本地服务可以留空。

先点 **测试连接**。看到「连接正常」后再点 **保存**。保存成功时，页面会提示新建实验在启动时读取这份配置。密钥只写入本机配置，设置页不会把已保存的密钥显示回来；留空表示保持不变。

没有可用的语言模型时，实验可以创建成草稿，但点击 **运行** 后 Agent 决策会失败。

### 向量模型

同一页的向量模型用于新闻检索，默认走 Embeddings 接口；Ollama 使用 `/api/embed`。同样先测试，再保存。

`embedding.yaml` 必须存在，模拟进程启动时会读取它。仓库自带的新闻向量索引是为特定向量模型生成的，更换模型后不能复用旧索引。需要重建时，见 [TwinMarket 模拟运行指南](SIMULATION_GUIDE_ZH.md)。

### 市场数据

第一次启动市场数据服务时，它会把仓库里已有的行情和新闻导入自己的数据仓库，并提供内置模板「A股 10 行业指数 · 日频」。默认日期 2023-06-15 至 2023-06-16 应能通过该模板的覆盖检查。

近期行情不在这份内置数据里。要同步新日期，在 **设置** 的「金融数据源」中填写 Tushare Token 并保存，再到 **市场** 里执行同步。第一次实验不必做这一步。

## 创建第一个实验

建议第一次就用表单里的默认规模：10 个 Agent、1 个并发 Worker、2023-06-15 至 2023-06-16。这两天足够确认模型、数据和页面是否接通。1000 个 Agent 或数周区间会按激活概率调用很多次模型，不适合作为第一次运行。

1. 打开 **实验**。空列表时，右上角是 **创建实验**。
2. 别名会自动填成「实验 1」这一类名称，可以改。描述可以留空。
3. 保持 Agent 数量 10、并发 Worker 1，以及上面的起止日期。结束日期不能早于起始日期。
4. 等「市场模板」不再显示「读取模板…」或「正在检查数据覆盖…」。默认模板的检查项都通过后，才能提交。若检查失败，把模板改成 **内置历史文件 · 旧版数据模式**，或缩短日期，直到 **创建实验** 可以点击。
5. 可选：展开「高级参数」。激活概率默认 0.2，10 个 Agent 时每天大约有 2 个会调用模型。技术面概率、Agent 超时和随机种子可以保持默认。
6. 点击表单底部的 **创建实验**。页面进入该实验的工作台，状态是 **草稿**，还没有开始交易日。

草稿只保存配置和输出目录，不调用模型。确认无误后，点击 **运行**。状态变为排队中或运行中，进度页开始显示当日阶段。需要中断时点 **停止**。

运行中可以看四项内容：

| 标签 | 用来确认什么 |
| --- | --- |
| 运行进度 | 当前阶段、已处理的 Agent，以及当日是否提交 |
| 分析 | 行情、交易行为、信息传播、典型事实和信息极化。样本太短时会说明原因 |
| 日志与诊断 | 运行日志和失败原因。日志一段时间没有更新，只说明文件不新鲜，不能单独当成进程已退出 |
| 配置 | 这次实验实际固定下来的参数 |

状态变成 **已完成** 后，列表上的 **结果** 会打开分析页。若状态是 **失败**，工作台会给出原因；已有成功提交的交易日时，**重试** 从下一日继续，否则从起始日重新运行。**已取消** 的实验用 **续跑**。草稿可以在「更多」里删除，删除后配置和输出目录不能恢复。已经运行过的实验只能归档。

不想用界面时，可以在命令行跑同一段日期：

```bash
cd backend
USER_COUNT=10 START_DATE=2023-06-15 END_DATE=2023-06-16 bash scripts/run.sh
```

命令行参数、监控和续跑见 [TwinMarket 模拟运行指南](SIMULATION_GUIDE_ZH.md)。
