  # 新功能2：交互式 Agent 关系图文档

  ## 概要

  新增 docs/新功能2_交互式关系图.md，使用以下发布信息：

  - title: 新功能2：交互式 Agent 关系图
  - published: true
  - category: 功能设计
  - order: 40

  文档将明确结论：功能可行，但现有数据只能直接支持“投资相似关系”；理想的双层
  关系图还需要补充不可变的社交互动事件、Web 安全快照和前后端接口。第一版放在
  Run 结果页的新“关系图”页签中，仅展示已提交的交易日快照。

  ## 文档内容

  - 说明当前真实数据：
      - build_graph_new() 每个自然日生成无向 NetworkX pickle。
      - 节点为 Agent，已有行业和分类属性。
      - 边表示带时间衰减的行业投资相似度，不是论坛社交关系。
      - 当前图还包含为孤立节点添加的兜底边，但没有字段区分兜底边与真实相似
        边。

      - 论坛数据库可以识别互动者、帖子作者、点赞、反对和转发，但 reactions 会
        覆盖旧状态，无法准确重建历史累计社交网络。

      - pickle 不应由浏览器读取，也不应在 HTTP 请求中直接反序列化。

  - 定义目标交互：
      - 图层支持“投资相似”“社交互动”“双层叠加”。
      - 时间轴只列出已经完成 commit 的交易日；周末互动累计进入下一个交易日快
        照。

      - 社交边为有向边，由互动 Agent 指向帖子作者，累计至所选交易日。
      - 固定节点坐标，拖动时间轴时只更新边、权重和节点指标，避免每日重新布局
        造成视觉跳动。

      - 支持缩放、画布拖动、节点搜索、邻居高亮、Agent 详情抽屉、行业图例、关
        系阈值过滤和键盘操作。

      - 使用短淡入淡出表现新增/消失边，并遵守 prefers-reduced-motion。
      - 推荐使用 AntV G6 5 的普通 Canvas 节点，不使用 React
        自定义节点；其官方接口支持 React 集成、JSON
        图数据、数据更新和大图视口优化：React 集成
        (https://g6.antv.antgroup.com/manual/getting-started/integration/react)、数据接口
        (https://g6.antv.antgroup.com/en/manual/data)、视口性能优化
        (https://g6.antv.antgroup.com/en/manual/behavior/optimize-viewport-transform)。

  ## 建议的数据与接口改造

  - 内核在每个自然日记录实际提交成功的不可变社交事件，包括 actor_id、
    target_agent_id、post_id、type、simulation_date 和状态转换；重复且未改变
    状态的操作不记为新事件。

  - 每个已提交交易日原子写入 relationship_graphs/<date>.json，并将该目录及社
    交事件目录纳入 resume 清理边界。

  - 投资边增加 origin: similarity | connectivity_fallback；时间衰减使用
    simulation clock，避免依赖机器当前时间。

  - JSON 快照包含：
      - 稳定的节点 ID、行业、分类、固定坐标和两层度数指标；
      - 无向投资边及相似度、边来源；
      - 有向社交边及累计 like_count、unlike_count、repost_count、
        total_count、signed_score；

      - 日期、交易日标记、节点/边统计、schema version 和数据覆盖状态。

  - 新增只读接口：
      - GET /api/runs/{run_id}/results/relationship-graphs：返回已提交交易日
        和每日日志摘要。

      - GET /api/runs/{run_id}/results/relationship-graphs/{date}：返回指定日
        期的完整快照。

  - 后端只读取并验证 JSON，不在请求路径加载 pickle；过滤超过 checkpoint 的未
    提交文件，并保留现有路径越界和符号链接防护。

  - 前端在 Results 页面增加 relationships 页签及强类型 DTO。拖动时间轴时取消
    过期请求、缓存最近快照并预取相邻日期。

  - 旧 Run 默认显示“缺少关系图 v1 快照”；不把缺失社交历史误报为零。可另行提供
    显式、可信的离线工具，仅回填投资层并标记社交覆盖不可用。

  ## 测试与验收

  - 验证投资边、兜底边和节点属性能无损转为 JSON 基础类型。
  - 验证点赞、反对、转发及状态切换只记录真实提交事件，并按交易日正确累计。
  - 验证休市日不产生时间轴刻度，但其社交事件进入下一个交易日快照。
  - 验证崩溃、续跑和边界清理不会暴露未 commit 或重复快照。
  - 验证后端拒绝非法日期、路径逃逸、损坏文件和错误 schema，且不会反序列化
    pickle。

  - 验证时间轴键盘操作、图层切换、节点选择、空状态、旧 Run 提示、请求取消及缓
    存命中。

  - 使用 1000 Agent 的代表性图测试；缓存快照切换目标低于 200 ms，并在平移、缩
    放时启用大图视口优化。

  ## 假设与默认值

  - 第一版关系语义为“双层关系图”。
  - 社交关系默认累计至所选交易日，而不是只显示当日事件。
  - 页面属于结果分析，不混入 Runtime 的运行阶段进度条。
  - 时间轴展示交易日，但数据生产继续允许内核按自然日运行。
  - 节点位置采用按行业分组、按 Agent ID 稳定排序的确定性布局；用户拖动节点只
    影响当前浏览会话。

  - 本次任务只新增功能设计文档，不实现内核、API 或前端代码。
