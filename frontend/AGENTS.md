# Studio Development Instructions

Confirmed product architecture (2026-09-12): the four primary spaces are Experiment, Agent, Market, Setting. Experiment owns experiment composition, runs, monitoring and analysis. Agent owns reusable Agent Groups and reserves behavioral-finance tests. Market owns mechanisms, asset packs, data synchronization and environment snapshots. Setting owns model/data-source credentials and extensible global defaults. Its current P0 is the real local simulation loop: configure a Run, start it, observe persisted RuntimeEvent progress, and inspect real results. Run controls and the Tushare settings, market synchronization, data versions and market-template selection workflows are active; market data comes from the standalone market data service through the `/mds` proxy (2026-10-26). Other resource-management write workflows remain planned. Preserve existing simulations and the research landing page.

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

UI framework decision (2026-10-18): Studio uses Radix Themes (accent teal, gray slate) instead of Animal Island UI. Button roles: primary `solid` (at most one per area), secondary `soft` gray, stop/delete `soft` red, inline `ghost`; run controls use one tone each (2026-10-23): run `solid` teal, resume `solid` blue, stop `soft` red, completed-run results `soft` iris; selection states use `SegmentedControl`/`Tabs`, never a primary button. Experiment space has two levels only: a list (table/card toggle, user-selectable columns including created/updated time) and a per-run workspace that merges running and results into tabs. Creating an experiment is a standalone page with breadcrumb and a safe back path (cancel returns to the origin; unsaved edits prompt before leaving). Agent views in the Agent space and the run workspace share `AgentExplorer` for the list and `AgentDialog` for detail: a single Agent's profile and context open as a dialog over the current page, so analysis views never navigate away to show an Agent (2026-11-06). `AgentDistribution` sits above the list in both places and summarizes each Agent's earliest snapshot, because `initial_positions` only holds zeros and later snapshots may blank the prompts; `AgentDialog` shows the raw persona prompts from that same snapshot in its 提示词 tab (2026-11-07). The Agent space has no page title: an intro paragraph based on the paper's Appendix D explains how personas are built, above the tabs 群体分布, 列表, 配置工作台 (`?view=`). The workbench is read-only until group write workflows exist. Single-choice distributions use pies with a figure list beside them; multi-select holdings and followed industries stay bars because their shares do not sum to a whole.

UI copy principle (2026-11-06): avoid unnecessary secondary labels and descriptions; let the layout do the explaining. `Panel` and `Stat` have no hint slot. Keep only text that changes what the user can do or that prevents a wrong reading (sample shortfalls, the synthetic banner, form behavior such as "留空保持不变").

Run analysis (2026-11-06): the run workspace has four tabs: 运行进度, 分析, 日志与诊断, 配置. `分析` (`src/experiments/AnalysisTab.jsx`) integrates the former Agents and results tabs as sub-views 行情, 交易行为, 信息传播, 典型事实, 信息极化, Agents (`?view=`), and reads `/api/runs/{id}/analysis/*`. There is no raw results table; trades and orders stay downloadable from 交易行为. The network timeline uses one node layout across all dates, so scrubbing moves edges rather than nodes. Views must show a reason instead of plotting when the sample is too small; seed history is drawn only as a labeled reference, never as simulated output. Runs with `config.synthetic_demo` (from `backend/scripts/generate_demo_run.py`) must keep their workspace banner: their data is generated and their stylized facts exist by construction.

Landing page (2026-10-24): the sidebar logo opens `/studio/Home`, a full-page landing (`src/Landing.jsx`) outside the app shell that presents the paper and Research Studio; its images live in `src/assets/landing/`.

Responsive preference: in portrait/mobile layouts, the primary space switcher is a fixed bottom navigation bar. Do not place the space-switching controls above the workspace content.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.
